# Command-line interface scenarios

1. Initialize a ledger, append one record from stdin, and read it back at the
   printed offset; the bytes round-trip exactly.
2. Append several records and scan; scan prints one OFFSET<TAB>LENGTH line per
   complete record, in iteration order, with nothing else on stdout.
3. Read a record that does not begin at a valid boundary, or beyond the end;
   the command fails with exit status 1 and writes no payload to stdout.
4. Check a clean ledger exits 0; check a ledger with an incomplete tail exits 1
   with a diagnostic on stderr; check an interior-corrupt ledger exits 1.
5. Repair removes an incomplete tail and later appends begin at the repaired
   boundary; repair of a clean ledger is a no-op that still exits 0.
6. Usage errors exit 2; runtime and integrity errors exit 1; diagnostics go to
   stderr only, machine output to stdout only.
7. A binary payload containing NUL and all 256 octet values survives append and
   read unchanged.
8. Concurrent `ledger89 append` processes each contribute exactly one record;
   scan reports every record exactly once.
9. Tail keeps a ledger open and prints each new record's raw payload to stdout
   as it completes; existing records are not replayed, a record mid-write at
   start is printed once it completes, and a missing path fails with exit 1.
10. A ledger created with a non-default reserve (via the library) is readable,
    scannable, appendable, tailable, and checkable by the CLI; the reserve is
    discovered from the preamble, matching the admin commands.

# Command-line interface scenarios

1. Initialize a ledger, append one record from stdin, and read it back at the
   printed record number; the bytes round-trip exactly.

2. Append several records and scan; scan prints one
   `INDEX<TAB>OFFSET<TAB>LENGTH` line per committed record, in order, with
   nothing else on stdout.

3. Read a record number that is out of range, or a non-numeric number; the
   former exits 1, the latter exits 2, and neither writes payload to stdout.

4. Count a clean ledger exits 0 and prints the exact record count on stdout.

5. Check a clean ledger exits 0; check a ledger with an incomplete tail exits 1
   with a diagnostic on stderr; repair removes the tail and reports what it
   removed; repair of a clean ledger is a no-op that still exits 0.

6. Usage errors exit 2; runtime and integrity errors exit 1; diagnostics go to
   stderr only, machine output to stdout only.

7. A binary payload containing NUL and all 256 octet values survives append and
   read unchanged.

8. Concurrent `ledger89 append` processes each contribute exactly one record;
   scan reports every record exactly once.

9. Tail keeps a ledger open and prints each new record's raw payload to stdout
   as it completes; existing records are not replayed, and a missing path fails
   with exit 1.

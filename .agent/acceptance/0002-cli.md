# Command-line interface acceptance

## Must exhibit

1. `ledger89 append` prints exactly one decimal offset (a record start) on
   stdout, followed by a newline, and nothing else.
2. `ledger89 read <path> <offset>` writes only the payload bytes of the record
   at that boundary to stdout, for binary payloads including NUL and all 256
   octet values.
3. `ledger89 scan` prints `OFFSET<TAB>LENGTH` lines, one per complete record,
   with no other stdout content.
4. `ledger89 init` creates a valid ledger and fails if the path already exists.
5. `ledger89 tail <path>` writes only the raw payload bytes of records that
   complete after it starts (nothing for existing records), and writes no
   diagnostics to stdout.
6. `ledger89 scan`, `read`, `tail`, and `append` discover the reserve from the
   file preamble, so they operate on a ledger created with any valid reserve,
   matching `check` and `repair`.

## Must reject

1. `ledger89 check` exits nonzero on an incomplete tail or interior corruption,
   and exits 0 only for a clean complete ledger.
2. `ledger89 read` on a non-boundary offset or a missing path exits nonzero.
3. A missing path or a directory fails every command with exit status 1.
4. `ledger89 tail` on a missing path exits 1; `tail` with extra arguments exits 2.

## Exit status

- 0 success
- 1 runtime, data, or integrity failure
- 2 usage error

## Unacceptable behavior

1. Writing diagnostics to stdout, or machine output (offsets, payloads, TSV)
   to stderr.
2. Exiting 0 after a failed append, read, check, or repair.
3. `read` emitting partial payload bytes when the record is incomplete.

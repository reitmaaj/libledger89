# Command-line interface acceptance

## Must exhibit

1. `ledger89 append` prints exactly one `NUMBER<TAB>OFFSET` line on stdout
   (the new record's 0-based number and its DATA offset), followed by a
   newline, and nothing else.

2. `ledger89 read <path> <N>` writes only the payload bytes of record N to
   stdout, for binary payloads including NUL and all 256 octet values.

3. `ledger89 scan` prints `INDEX<TAB>OFFSET<TAB>LENGTH` lines, one per
   committed record, with no other stdout content.

4. `ledger89 count` prints the committed record count as a single decimal
   integer on stdout.

5. `ledger89 init` creates a valid ledger and fails if the path already exists.

6. `ledger89 tail <path>` writes only the raw payload bytes of records that
   complete after it starts, and writes no diagnostics to stdout.

## Must reject

1. `ledger89 check` exits nonzero on an incomplete tail, and exits 0 only for a
   clean complete ledger.

2. `ledger89 read` on an out-of-range record number exits 1; a non-numeric
   number exits 2.

3. A missing path or a directory fails every command with exit status 1.

4. `ledger89 tail` on a missing path exits 1; `tail` with extra arguments exits 2.

## Exit status

- 0 success
- 1 runtime, data, or integrity failure
- 2 usage error

## Unacceptable behavior

1. Writing diagnostics to stdout, or machine output (numbers, payloads, TSV)
   to stderr.

2. Exiting 0 after a failed append, read, check, or repair.

3. `read` emitting partial payload bytes when the record is unavailable or
   corrupt.

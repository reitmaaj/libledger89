# Command-line interface acceptance

## Must exhibit

1. `ledger89 append` prints exactly one decimal payload offset followed by a
   newline on stdout, and nothing else.

2. `ledger89 scan` writes only the raw payload bytes of each record to its
   `INDEX<TAB>OFFSET<TAB>LENGTH` line form; binary payloads including NUL and
   all 256 octet values are preserved.

3. `ledger89 count` prints the committed record count as a single decimal
   integer on stdout, computed by iteration.

4. `ledger89 init` creates a valid ledger and fails if the path already exists.

5. `ledger89 tail <path>` writes only the raw payload bytes of records that
   complete after it starts, and writes no diagnostics to stdout.

## Must reject

1. `ledger89 check` exits nonzero on an incomplete tail, and exits 0 only for
   a clean complete ledger.

2. A missing path or a directory fails every command with exit status 1.

3. `ledger89 tail` on a missing path exits 1; a command with extra arguments
   exits 2.

## Exit status

- 0 success
- 1 runtime, data, or integrity failure
- 2 usage error

## Unacceptable behavior

1. Writing diagnostics to stdout, or machine output (numbers, payloads, TSV)
   to stderr.

2. Exiting 0 after a failed append, scan, check, or repair.

3. Emitting partial payload bytes when a record is corrupt.
